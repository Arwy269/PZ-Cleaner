# 🧟 僵毁区块重置器（网页版）

在 Windows 僵尸毁灭工程（Project Zomboid）**专用服务器**上运行的小工具：
在地图上框选范围，**直接删除存档里的区块文件**，重启服务器后该区域整块重新生成
（地形、建筑来自地图包，战利品与丧尸按世界时间重新刷新）——不依赖任何游戏 API / MOD。

- 底图与坐标：**pzmap.org** 的 B42 等距渲染瓦片（Cloudflare 拦截由内置 curl_cffi 自动绕过；
  失败时自动回退开源镜像 pzmap.net）
- 界面：本地网页（启动后自动打开浏览器）
- 删除：默认先备份，可一键还原

---

## 一、快速开始（在服务器上）

1. 把 `僵毁区块重置器.exe` 拷到服务器任意目录（无需安装 Python）。
2. **先停止僵毁服务器**（关掉服务器进程/窗口）。
3. 双击 `僵毁区块重置器.exe`，浏览器会自动打开 `http://127.0.0.1:8765`。
4. 顶部选择存档（默认会找 `C:\Users\Administrator\Zomboid\Saves\Multiplayer\servertest`，
   也可以手动输入任意存档路径）。
5. 地图上点击 **「框选模式」**，按住鼠标拖拽框出要重置的区域（按住 `Ctrl` 拖拽 = 追加选择）；
   也可以在左侧直接输入**中心坐标 + 宽高**（单位：世界方格）来选择。
6. 左侧确认信息：选中多少区块、其中多少个存档文件存在、体积多少。
7. 选择删除方式（推荐"备份后删除"），在确认框输入 **删除**，点 **执行重置**。
8. 启动服务器，所选区块已整块重新生成。

自检（可选）：

```
僵毁区块重置器.exe --smoke
```

会输出 JSON：依赖、底图源、存档扫描、进程检测是否正常。

## 二、安全机制

| 机制 | 说明 |
| --- | --- |
| 进程检测 | 每次删除前用 PowerShell 检测 `ProjectZomboid` / `zombie.network.GameServer` 进程，**运行中会拒绝执行** |
| 无法检测时 | 需要手动勾选「我已确认服务器已停止（强制执行）」 |
| 输入确认 | 必须手动输入「删除」两个字按钮才可点 |
| 备份 | 默认把文件**移动**到 `exe 同目录\区块备份\<存档名_时间戳>\`，保留 `X/Y.bin` 目录结构 |
| 还原方法 | 把备份里的文件按原路径拷回 `map` 目录即恢复 |
| 单次上限 | 一次最多 200000 个区块，防止误框全图 |

## 三、工作原理

- **B42**（当前版本，42.x）：存档中每个区块 = `map/<X>/<Y>.bin` 一个文件，
  其中 `X = 世界x ÷ 8`、`Y = 世界y ÷ 8`（1 区块 = 8×8 个世界方格，由存档实测验证）。
  删除文件后，服务器加载到该位置时发现没有存档数据，就会按地图包重新生成整块内容。
- **B41**：兼容 `map/r<X>_<Y>.bin` 平铺格式（1 区块 = 10×10 方格，按配置换算）。
- 地图坐标换算使用 pzmap2dzi 渲染参数（`map_info.json` 的 `x0/y0/sqr/scale` + DZI 深度缩放金字塔），
  与 pzmap.org 网页完全一致，鼠标悬停显示的世界坐标即游戏内坐标。

> 说明：`zpop/apop/chunkdata` 等 metacell 级统计数据不随单区块删除（格式不公开，不敢乱动），
> 游戏会在区块重新生成后自行处理，实测不影响开服。

## 四、配置文件 `config.json`（exe 同目录，首次选择存档后生成）

```json
{
  "port": 8765,                          // 监听端口（被占用时自动 +1~+20）
  "host": "127.0.0.1",                   // 改成 0.0.0.0 允许局域网访问
  "save_roots": [
    "C:\\Users\\Administrator\\Zomboid\\Saves\\Multiplayer"
  ],                                     // 自动扫描这些目录下的所有存档
  "selected_save": "上次选中的存档",
  "chunk_divisor": 8,                    // B42: 1 区块 = 8×8 方格
  "chunk_divisor_b41": 10,               // B41: 1 区块 = 10×10 方格
  "backup_root": null,                   // null = exe 同目录\区块备份
  "map_source": "auto"                   // auto | pzmap.org | pzmap.net
}
```

其他目录：

- `mapcache\` — 底图瓦片缓存（可整个删除，会自动重新下载）
- `区块备份\` — 删除前的备份
- 命令行：`--port 9000`、`--host 0.0.0.0`、`--save <存档map路径>`、`--no-browser`、`--smoke`

## 五、从自己电脑远程操作服务器（可选）

工具默认只监听 `127.0.0.1`（只有服务器本机能访问）。要从自己电脑打开：

```
僵毁区块重置器.exe --host 0.0.0.0 --port 8765
```

然后在服务器防火墙放行该端口（或仅对内网开放），浏览器访问 `http://服务器IP:8765`。
注意：这样任何人都能操作删除，**务必只对可信网络开放**。

## 六、常见问题

**Q: 双击后打不开网页？**
用 `--no-browser` 启动，然后手动访问终端里打印的地址（默认 `http://127.0.0.1:8765`）。

**Q: 底图一直加载中 / 底图不可用？**
服务器需要能访问 `tiles.pzmap.org`。若网络受限，可在 `config.json` 把 `map_source`
改为 `pzmap.net`，或整体离线：提前在能上网的机器上打开一次工具让 `mapcache\` 缓满，
再把 exe 目录连缓存一起拷过去。

**Q: 地图图片加载慢？**
工具已内置多级加速，正常表现是"第一次稍慢、之后秒开"：

- 底图投影参数落盘缓存：首次获取约 1~2 秒，之后启动 60ms 级
- 瓦片磁盘缓存 + TLS 连接复用：每块首次下载约 1~2 秒，之后 **约 60ms**
- 视野移动/缩放后自动**后台预取**周围最多 64 块，平移时大概率已缓存
- 状态栏实时显示 `瓦片 x/y · 上游 xx ms`，可据此判断是本地慢还是上游慢
- 反复浏览过的区域完全走本地缓存，离线也能看

若上游始终很慢（服务器在国外/网络差），把 `config.json` 的 `map_source` 改为
`pzmap.net` 试试；或在网速好的机器上预热 `mapcache\` 后整目录拷贝到服务器。

**Q: 提示"检测到服务器进程正在运行"但其实已经关了？**
进程检测每 15 秒刷新一次，点左侧信息区重新检测；确认无误后可勾选强制执行。

**Q: 选区后"已存在文件 0 个"？**
说明该范围没有存档文件（没被玩家探索过），无需重置——框到有青色方块的区域。

**Q: 删除后想恢复？**
把 `区块备份\<存档名_时间戳>\` 里的 `X/Y.bin` 拷回存档的 `map` 目录对应位置。

**Q: 杀毒软件报警？**
PyInstaller 单文件 exe 常见的误报（打包器同质化）。可改用源码方式运行：
装个 Python 3.10+，在 exe 目录执行 `python server.py`（需要 `pip install curl_cffi`）。

## 七、源码与重新打包

```
区块重置器\
├── server.py          # 后端（Python 标准库 + curl_cffi）
├── static\            # 前端页面 + 内置 Leaflet
├── config.json        # 运行时生成
├── mapcache\          # 瓦片缓存（运行时生成）
└── dist\僵毁区块重置器.exe
```

重新打包：

```
pip install pyinstaller curl_cffi
python -m PyInstaller --noconfirm --onefile --name "僵毁区块重置器" ^
       --add-data "static;static" --collect-all curl_cffi server.py
```

开发调试：`python server.py --no-browser --port 8790`
（页面支持 `?sel=中心X,中心Y,宽,高` 快速定位选择，例如 `?sel=8272,9468,48,24`）
